# Cartcut end-to-end render suite

Launches the real app, builds a project containing every element type the editor
supports, clicks the real Render button, and then checks — frame by frame —
that the file that came out is the film the timeline described.

It is a stress test by construction. The `full` profile puts twenty-plus clips
across a dozen codecs, five overlapping audio tracks, transitions, shader
effects, groups and three hundred keyframes through 18,000 frames of 1080p60
export in one go.

```
npm run test:e2e:fixtures     # download and build the media (once, ~150 MB)
npm run test:e2e:smoke        # 20s @ 640x360x30  — ~1 min, for iterating
npm run test:e2e:smoke120     # 20s @ 640x360x120 — ~2 min, the top of the rate band
npm run test:e2e              # 5 min @ 1920x1080x60, 18,000 frames
npm run test:e2e:extreme      # 5 min @ 3840x2160x60 — run by hand
```

The frame rate is a profile axis, not a constant: every spec drives it through
the settings panel (`harness/ui.ts#setFps`) and reads it back off the store, and
each profile's instruments are generated at that profile's rate — which is why
`export-path` and `seek-diagnosis` take `fps` from `profile` rather than naming
one. `smoke` and `smoke120` are the same project at 30 and 120fps, so a
difference between them is a frame-rate assumption and nothing else.

**Read [FINDINGS.md](./FINDINGS.md) for what it found**, including the defect it
was built to catch: a third to two thirds of every export carried the previous
source frame, because a frame was addressed at its boundary rather than its
centre. That one is fixed and verified — 0 wrong frames out of 18,000 at
1080p60 — and eight other findings are reported but not fixed.

`CARTCUT_E2E_ALLOW_KNOWN_SEEK_OFFSET=1` downgrades the frame-index assertions to
soft failures. It exists so the checks *after* that one can still be exercised
while such a defect is open; it is not needed now and should stay unset.

## What it does to the app

Nothing. It runs against an isolated `--user-data-dir`, so the developer's own
project, settings and MCP token are untouched, and it seeds `mcp_autostart:
false` into that throwaway store so it never contends for port 9826 with a real
editor. Both native dialogs are stubbed **in the main process at runtime**, so
`electron/ipc/ipcDialog.ts` has no idea a test exists and the Render button is
genuinely clicked.

Three files of production code changed to make this possible, none of which
alter behaviour:

- `apps/app/src/features/export/renderers.ts` — new. The renderer table that was
  inline in the old `ControlRender` panel, so the reference render and the
  export provably use the same one.
- `apps/app/src/features/export/exportSession.ts` — uses that constant.
- `apps/app/src/index.ts` — extends the diagnostics already exported on
  `window.CARTCUT` (documented there since before this suite) with pure
  re-exports of `renderTimelineAtTime`, the stores and the FX runtime factories.

## How it drives the editor

**By clicking**, wherever the wiring is what is under test: the settings and
export codec panel (`#nav-home`, opened with `openSettingsTab`), the
sidebar tabs, the fx preset grid, and Render itself.

**By command**, for bulk placement — twenty clips and three hundred keyframes
driven by synthetic mouse events would add flake without adding coverage. Those
go over the `agent:request` / `agent:response` IPC the app already ships for
Claude Code, which per CLAUDE.md runs the same pure ops and records the same
single undo step as the mouse. Reached from the main process, so no MCP port and
no bearer token are involved.

## How it decides a frame is right

Ordinary footage cannot answer "is exported frame N the frame the timeline has
at N/fps?". Measured on this repo's own ffmpeg, a full one-frame shift moves
whole-frame mean absolute error from 1.05 to 1.50 — inside codec noise — and
SSIM from 0.9987 to 0.9886, above any threshold that would not flake.

So the project carries four purpose-built instruments in bands around the
content, generated by `fixtures/instruments.mjs`:

| band | what it answers |
|---|---|
| `code` | *Exactly* which frame is this — an integer read from binary patches, zero tolerance |
| `ticker` | A continuous alignment score, so a shift's direction is recoverable |
| `swatch` | Did the RGB→YUV→RGB round trip stay honest — eight known colours, absolute |
| `sync` | A click and a flash generated on the same frame numbers, in one function |

`content` is the band between them, and it is the only region any fidelity
metric reads.

The `code` band makes the strongest assertion in the suite nearly free: crop to
the band, scale it to one pixel per bit with nearest-neighbour sampling, and
every frame of the file yields 15 bytes instead of 8.3 MB. **All 18,000 frames**
get their index checked in about seven seconds.

### Thresholds

Every number is calibrated against a measured floor, not guessed. The floor is
not zero — the export writes full-range RGBA into 4:2:0 H.264 and the decode
comes back through the same conversion — and it depends on the content, so it
is measured against the footage the scenario actually composites rather than
against a synthetic frame:

| metric | threshold | synthetic floor | real-footage max over 94 frames |
|---|---|---|---|
| `mean` | 4.0 | 1.07 | 2.16 |
| `p99` | 24 | 4 | 14 |
| `p999` | 72 | 11 | 51 |
| `frac(Δ>24)` | 2 % | 0.008 % | 0.5 % |
| `max` | **not asserted** | 115 | 157 |

`max` is deliberately absent: a *correct* round trip reaches 115, so any
max-based assertion is a coin flip.

These catch *wrong content* — a missing element, a mangled transform — not a
wrong frame. That distinction is load-bearing: when the frame-addressing defect
was live and two thirds of frames were wrong, these numbers sat in the same
range they sit in now, because consecutive frames of real footage look alike.
`mean` and `frac(Δ>24)` are the real gates; `p99`/`p999` are dominated by chroma
ringing on detailed content and are kept only as sanity ceilings.

### Colour

The decode forces nothing. `ffmpegArgs.ts` writes no colour tags, so swscale
converted with its defaults and ffmpeg decodes with the same ones — the round
trip is self-consistent, and every forced override measured *worse* (bt709:
green off by 42; full-range: mean 9.79 against 1.07). Forcing would also rot
silently the day someone correctly adds tagging. The `swatch` canary checks the
round trip empirically instead, and when it fails it *replaces* the fidelity
assertions rather than adding to them.

## Layout

```
profiles.json          the four scales, in one place
fixtures/
  plan.mjs             what to download and what to derive from it
  instruments.mjs      the measuring instruments, and why each is built that way
  geometry.mjs         where the bands sit — shared with the specs
  fetch.mjs            the executor; writes .fixtures/manifest.json
harness/
  launch.ts            isolated launch, dialog stubs, readiness
  agent.ts             editor commands over the shipping IPC
  ui.ts                clicking the real controls
  export.ts            the Render button, progress, stall detection
  decode.ts            ffprobe, the exhaustive index map, frame extraction
  compare.ts           metrics, thresholds, the canary, the alignment search
  reference.ts         re-rendering a frame the way the export renders it
  audio.ts             silence, RMS envelope, loudness
  artifacts.ts         PNG writer, threshold-banded heat map, side-by-sides
scenario/
  kitchenSink.ts       the project itself
  sampling.ts          which frames get looked at, declared as anchors
specs/
  launch.spec.ts       the floor everything else stands on
  agent.spec.ts        the command channel
  export-path.spec.ts  the narrowest end-to-end export, for triage
  blend.spec.ts        blend modes, against arithmetic rather than a reference
  lut.spec.ts          colour LUTs, the same way — plus adjustment layers,
                       intensity, and a LUT installed by hand
  lut-panel.spec.ts    the LUT tab paints its tiles when it is opened
  seek-diagnosis.spec.ts  seek fidelity, with no encoder in the way
  stress.spec.ts       the run
```

## When it fails

`.out/<profile>/<test>/` gets, per mismatched frame, the reference render, the
decoded frame, a side-by-side, and a heat map coloured by *threshold band*
rather than by magnitude — codec noise comes out as faint blue tracing the
edges, a real fault as a solid red shape. Plus `index-map.json` (run-length
encoded; `[]` means perfect), `ffprobe.json`, the FFmpeg stderr tail,
`scenario.json`, and `project.ngt` so a failure can be re-rendered without
rebuilding the timeline.

Frames are named by what they are, not by number, so a failure reads

```
clipEdge(main:v07-longgop, out, -1): frame carries index 298, expected 299
```

## Known limits

- **Network is required.** `apps/app/index.html` pulls Bootstrap, Popper,
  SweetAlert2 and the DeVent design system from jsDelivr, and the export modal
  goes through `bootstrap.Modal`. `launch.ts` fails with that explanation rather
  than letting it surface as a mysterious export error.
- **The preview leg asserts presence, not pixels.** `previewCanvas.ts` composites
  the scene at device size under the viewport's zoom, over a dimmed copy of
  itself, with frame guides and selection chrome — there is no pixel-comparable
  region without inverting that transform. What it does assert is the bug worth
  catching: the preview must not be blank where the export has content, or the
  reverse, which is exactly how a stale `renderVideoWithoutWait` frame shows up.
- **`extreme` has not been run to completion.** 4K raw frames are 33 MB each,
  which halves `inFlightWindow`; expect hours.
- **`blend.spec.ts`, `lut.spec.ts` and `lut-panel.spec.ts` need no
  fixtures.** Their scenes are solid-colour shapes, so there is nothing to
  download and nothing to decode on the way in — which is also what lets them
  assert exact colours instead of metrics. They can be run on their own before
  `npm run test:e2e:fixtures` has ever been run:

  ```
  npx playwright test -c tests/e2e/playwright.config.ts \
    --project=smoke tests/e2e/specs/blend.spec.ts tests/e2e/specs/lut.spec.ts
  ```

  They also set their own three-second duration rather than taking the profile's,
  so it costs about the same under `full` as under `smoke`.
